# WMR Universal Developer Trace Dashboard v2.8

[![Validate](https://github.com/pgpaolo/weewx-wmr-developer-trace-dashboard/actions/workflows/validate.yml/badge.svg)](https://github.com/pgpaolo/weewx-wmr-developer-trace-dashboard/actions/workflows/validate.yml)

Standalone PHP diagnostics dashboard for the hardened WeeWX Oregon Scientific WMR drivers.

Supported protocol families include:

- WMR100 / WMR100N
- WMR88 / WMR88A
- WMR180 / WMR180A
- WMRS200
- WMR200 / WMR200A

The dashboard reads the structured JSONL developer traces generated by the hardened drivers. It can automatically select the currently active trace or use an explicitly selected trace file.

> **Diagnostics tool:** this dashboard is intended primarily for troubleshooting and temporary technical monitoring. Do not expose it permanently to the public Internet without an authentication or access-control layer.

## Current version

**v2.8**

v2.8 keeps the WMR200 behavior unchanged while improving WMR100/WMR88 pressure and forecast interpretation:

- native `forecastIcon` support when supplied by newer WMR100/WMR88 hardened drivers;
- verified fallback to the raw pressure packet `0x46` for older compatible traces;
- separate display of station/absolute pressure and console relative pressure / SLP;
- no longer labels WMR100/WMR88 console relative pressure as `altimeter`;
- WMR200 continues to use the `altimeter` value supplied by its driver;
- live-cache schema version 5 prevents stale state inherited from v2.7.

The WMR100/WMR88 forecast code is transmitted by the console. The dashboard does **not** calculate the forecast from pressure or pressure trend.

## Trace sources

Automatic detection checks the known traces, including:

```text
/var/log/weewx/wmr100-developer-trace.jsonl
/var/log/weewx/wmr200-developer-trace.jsonl
/tmp/wmr200-developer-trace.jsonl
```

The active source is selected using the newest trace event timestamp.

Manual trace mode is deliberately restricted to readable `.jsonl` files below:

```text
/var/log/weewx
/tmp
```

These restrictions are a security boundary and should not be broadened casually.

## Automatic and manual source mode

The dashboard provides an explicit source selector:

```text
Automatico | Manuale
```

In **Automatic** mode, the newest known trace is selected.

In **Manual** mode, only the requested trace file is used. The source mode, selected parser/family and manual trace path are remembered in same-origin `SameSite=Lax` cookies.

No credentials or trace contents are stored in these cookies.

## Live monitoring

The dashboard maintains incremental live state rather than rebuilding all weather state from a fixed tail at each AJAX refresh.

It handles:

- normal JSONL growth;
- partially written final JSONL records;
- trace rotation or truncation;
- live weather values;
- packet/session counters;
- protocol health information;
- recent USB/protocol warnings;
- family-specific panels.

RF/channel information is shown for the WMR100/WMR88 family and is hidden for WMR200/WMR200A.

## Forecast and pressure

### WMR100 / WMR88

The Pressure card distinguishes:

- **Station / absolute pressure**
- **Console relative pressure / SLP**

Forecast source priority is:

1. driver-provided `forecastIcon`, when available;
2. raw native pressure packet `0x46` compatibility fallback.

### WMR200 / WMR200A

The dashboard keeps the WMR200 behavior unchanged and displays the pressure, `altimeter` and forecast information supplied by the hardened WMR200 trace.

## Diagnostic bundle

The dashboard can generate a diagnostic bundle containing a bounded set of recent trace events and a summary.

A bundle can include technical details such as:

- driver version and model;
- USB VID/PID and endpoint metadata;
- timestamps;
- error reasons and counters;
- selected packet contents;
- local trace paths.

**Always review a diagnostic bundle before publishing or sharing it.**

## Installation

Copy `index.php` to the desired web directory.

Example:

```bash
sudo cp index.php /var/www/html/wmr-trace/index.php
sudo chown root:root /var/www/html/wmr-trace/index.php
sudo chmod 0644 /var/www/html/wmr-trace/index.php
```

Validate the PHP syntax:

```bash
php -l /var/www/html/wmr-trace/index.php
```

Expected result:

```text
No syntax errors detected in /var/www/html/wmr-trace/index.php
```

The web-server user must have read permission on the active developer trace.

Examples:

```bash
sudo -u www-data head -1 /var/log/weewx/wmr100-developer-trace.jsonl
sudo -u www-data head -1 /var/log/weewx/wmr200-developer-trace.jsonl
```

## Recommended driver trace configuration

For detailed packet and live-weather diagnostics, keep packet tracing enabled in the corresponding hardened driver.

Typical WMR100/WMR88 configuration:

```ini
developer_trace = true
developer_trace_packets = true
```

Typical WMR200 configuration:

```ini
developer_trace = true
developer_trace_include_packets = true
```

The exact option names depend on the hardened driver version in use.

## GitHub workflow

The repository includes a lightweight GitHub Actions workflow that:

- runs PHP lint;
- validates the expected dashboard version in `index.php`, `README.md`, `README-IT.md` and `CHANGELOG.md`;
- runs on pushes to `main`, pull requests targeting `main`, and manual dispatch.

The dashboard currently uses a simple single-branch model. A permanent `develop` branch is not required unless future development becomes more frequent or experimental.

## Security

Read [SECURITY.md](SECURITY.md) before exposing the dashboard outside a trusted network.

The most important rules are:

- do not expose the page permanently without access control;
- do not broaden the allowed manual trace roots without reviewing the security impact;
- review diagnostic bundles before sharing them;
- keep the web server and PHP installation updated.
